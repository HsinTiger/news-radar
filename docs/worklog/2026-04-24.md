## 2. 關鍵發現 / 決策

### 2.1 Reuters CDN hot-link 防禦會整個 break publish

Reuters 的 `resizer.v2` 圖片 URL 有三重門：
- `Referer: https://www.reuters.com/`（browser 帶、Meta fetcher 不帶）
- `User-Agent` 檢查（不明確，但疑似也擋）
- `auth=...` token（時效性簽章，Referer 通過就不卡，Referer 失敗就算新 token 也 403）

對 Meta Graph API 的後果：
- **FB** `code 324` "Missing or invalid image file"
- **IG/Threads** `code 2207052` "影音素材下載失敗"

這個模式很可能對 **Bloomberg / WSJ / FT / NYT** 全部適用。沒驗證過，但當事人都用類似 CDN + auth token，機率高。下次這類來源出問題，先不 debug publisher，直接 `--auto-rehost` 測試。

### 2.2 「re-host 到 GitHub raw」是最省事的解

考慮過的選項：
- (a) S3 / Cloudinary / imgbb：要 auth、要 billing、要多一個依賴
- (b) Unsplash / Pexels API：拿的是 stock photo，不是文章真正的圖，失真
- (c) 抓原圖 → 本機 + Mac 的 Nginx：公網不可達
- (d) **GitHub raw**：`raw.githubusercontent.com/<user>/<repo>/main/assets/xxx.jpg`
  - 免費、公開、穩定、Meta 抓得到（200 OK 驗證過）
  - Repo 是 public 本來就在 → 無額外 infra
  - Git log 天然是 audit trail

選 (d)。代價：每次 emergency 發文會多一筆 `chore(assets): ...` commit 跟一次 push，但單位成本 < 1 秒。

### 2.3 Retry 不重 compose，只重 publish

第一次跑 emergency_oneshot 時 compose 花了 157 秒 + 一次 LLM call。publish 掛掉後如果整條重跑就浪費這個成本。

所以 `tools/retry_publish.py` 的合約是：
- 輸入：`draft_id` + 新 `--og-image`
- 從 DB 讀現成的 `platform_drafts.full_text`（不重 compose、不重 score）
- 每個平台查最近一筆 `publish_log.success`：`=1` 就跳過（不重發）、`=0` 或無 row 就重發
- 三平台全 success → 才 `mark drafts.status='published'`、`news_items.status='published'`、更新 `og_image_url`

這個設計保留了**所有 FAIL row**當 audit trail。今天 Reuters 那篇在 DB 裡有 6 筆 publish_log（3 FAIL + 3 SUCCESS），以後回查「為什麼 13:07 失敗」還找得到錯誤訊息。

### 2.4 Dashboard 的 emergency 標記從 `feed_name` 推，不用加新 column

原本以為要加 `drafts.origin` column、改 API、改前端——可是 `news_items.feed_name='emergency_manual'` 這個訊號在 `emergency_oneshot.py` 寫 DB 時已經有了。dashboard 端只要 derive：

```js
isEmergency(item) => (item.feed_name || '').toLowerCase().startsWith('emergency')
```

零 schema 改動、零 backend 改動，只在 `src/lib/origin.js` 加 helper，然後在 Archive / Home 的兩個地方 render `EmergencyBadge`。

### 5.1 Emergency 發文流程已穩定，下次直接跑

```bash
bash tools/emergency_oneshot.sh "https://..." \
     --pdf ~/Downloads/x.pdf \
     --title "..." \
     --auto-rehost         # ← 關鍵，不用再手動處理圖
```

`--auto-rehost` 的前提：你在 `main` branch、`git push` 有權限（一般都有）、圖下得下來。失敗會 `exit 3` 不繼續。

### 5.2 如果 publish 途中掛了

Python 已經 commit 了 drafts 跟 platform_drafts，但 publish_log 三筆 FAIL。不要整條重跑：

```bash
python tools/retry_publish.py <draft_id> --og-image <new_url>
bash scripts/push_state.sh --expect-draft <draft_id>
```

`<draft_id>` 從 `tools/.last_emergency_draft_id` 讀。

### 5.3 如果 Reuters 以外的 CDN 也 block Meta

直接試 `--auto-rehost`。大多數 CDN 對 `Referer: https://www.<host>/` 就放行（`image_rehost.py::_infer_referer`）。

如果連 re-host 下載都 403，那個 CDN 要特殊處理——看 `_BROWSER_UA` + `_infer_referer` 要不要加該 host 的特例。

### 5.4 Dashboard 現在有 `origin` 概念

- DB 端來源：`news_items.feed_name`（emergency_manual 開頭的就是手動）
- 前端 helper：`src/lib/origin.js`

Mock mode 看不到（因為 MOCK_ITEMS 裡沒 emergency 樣本）。要看要切 live mode（`npm run dev:live`）+ DB 裡有 emergency_manual row（目前有一筆）。
