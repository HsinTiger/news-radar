## Design choices baked in (revisit if composer-driven optimization underperforms)

These are deliberate trade-offs. If proposals.jsonl shows composer rules consistently producing low-quality / off-brand drafts after calibration period, this is the list to revisit:

1. **Anti-pattern filter explicitly upstream + `anti_patterns_filtered` output field.** LLM is forced to surface filtered patterns rather than silently ignore. Future PM review of proposals can grep `anti_patterns_filtered != []` to verify the brand-DNA gate is engaging.

2. **Numeric confidence cutoffs** (HIGH = ≥3 top-Q occurrences with 0 bot-Q; MED = ≥2 / ≤1; LOW = single occurrence). Removes LLM's freedom to label confidence subjectively. If too few HIGH proposals surface, lower threshold OR widen lookback window beyond 14d.

3. **Hard cap of 5 rules total** (body + hook combined). Prevents LLM from rule-padding to look productive. Each extra rule = extra constraint on composer's writing latitude. Revisit if early calibration shows analyzer regularly hitting cap (signal: real rules being squeezed out).

4. **Default no LOW confidence proposals.** Calibration phase requires per-item Hsin approval; LOW-confidence noise wastes review attention. Revisit if early calibration shows MED/HIGH proposal volume too thin (under 1-2/week), then unlock LOW.

5. **Evidence quote MUST be verbatim from a top-Q draft** (≤30 chars). Hallucination protection. If LLM struggles to surface short verbatim quotes, may indicate samples too long (truncate body further) OR genuine pattern is structural not lexical (different prompt design needed).

6. **Voice-tone changes explicitly forbidden in rule output** (no emoji additions, no length adjustments, no person-pronoun shifts). Aligned with `feedback_reflector_scope` memory: reflector scope = engagement optimization, NOT brand stewardship. Brand DNA stays in `news_radar_soul.md` + KOL benchmarks (curated layer, not data-driven).

## When to revisit

Trigger conditions for re-examining these design choices:
- Calibration period (6-8 weeks post Phase 9 ship) shows ≤30% Hsin-approval rate on composer proposals (most rules being rejected) — implies rules don't match Hsin's brand intuition.
- Proposals.jsonl `anti_patterns_filtered` field consistently empty across 4+ weekly runs — implies the filter isn't engaging (either rules are all clean, or LLM not surfacing filters).
- Composer rule deployment doesn't lift engagement above pre-Phase-9 baseline after 8+ weeks — suggests rule extraction from quartile diff isn't capturing the right signal.
- Brand drift detected (KOL-benchmark fit degraded per Hsin's own dogfood read of pipeline output) — composer rules may have engagement-overfit despite anti-pattern filter.

Revisit means: re-read this section, re-examine each numbered choice, decide which to relax / tighten / remove. Rule of thumb: tighten if proposals are noisy, relax if proposals are too sparse.
