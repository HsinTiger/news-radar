# 框架：反面論證的建構

> 蒸餾自 `notes/` 全部 92 篇共有的「反面／風險」一節，取樣驗證於
> `notes/45`（AI 末日論）、`notes/35`（私募信貸）、`notes/03`（Bending Spoons）。
> 用途：任何要下判斷的文章或 thesis card，反面必須用這個規格寫。

## 為什麼要有規格

「有風險」「需持續觀察」「市場波動可能影響」——這些不是反面論證，
是免責聲明。它們的共同缺陷是**無法被觸發**：沒有任何未來事件能證明它對或錯，
所以它對決策沒有任何影響。

曼報每篇筆記的反面都可觸發。三個共同特徵：

1. **具名**：有一個可以稱呼的名字（往上無處可逃、溫水煮青蛙、產能瓶頸）
2. **條件式**：「若 X 成立 → 則機制 Y 失效」，不是「Y 可能不好」
3. **攻擊承重假設**：打的是主論點賴以成立的那一根柱子，不是週邊風險

## 四種反面的型態（照這個清單掃，避免只想到一種）

| 型態 | 打的是什麼 | 樣本 |
|---|---|---|
| **假設失效** | 主論點依賴的歷史類比或前提不再成立 | AGI 若在所有認知維度超越人類，「人類總能找到新工作」的歷史經驗整個失效（`notes/45`） |
| **力道不足** | 每個機制都在運作，但總和補不上缺口，系統悄悄逼近臨界 | 溫水煮青蛙：微幅降價與部分新職缺都有，就是不夠（`notes/45`） |
| **二階傳導** | 一階沒事，但它引發的下一層讓防線失效 | 軟體公司被顛覆 → EBITDA 趨零 → 清算回收率遠低於實體資產 → 債權人最上層的 LTV 防線失效（`notes/35`） |
| **結構天花板** | 模式本身有無法擴張的物理/組織上限 | 改造工作高度介入，受限於核心員工人均產能，產能不足就得放棄收購（`notes/03`） |

四種都掃過再寫。只寫得出一種，通常代表對主論點的理解還不夠深。

## 寫作規格

每條反面必須包含三個部分，缺一不可：

```
**〔名字〕**：〔條件〕→〔哪個機制失效〕→〔觀測指標〕
```

- **名字**：讓它可以在後續討論中被指涉。無名的風險會被遺忘。
- **條件**：具體到可以判斷有沒有發生。「市場變差」不行，
  「贖回閘門被觸發」可以。
- **觀測指標**：你要看哪個數字/事件才知道它正在發生。
  **沒有觀測指標的反面等於沒寫**——因為你永遠不會發現它成真了。

## 與「證偽條件」的關係

反面論證是**分析**，證偽條件是**紀律**。反面說「這個判斷在什麼情況下會錯」，
證偽條件說「錯了的話我要做什麼」。

一條合格的反面，應該能直接轉寫成證偽條件：

```
反面   ：**融資管道反噬**：若標的價格下跌同時 ATM 增發停擺 →
         被迫在最差價格賣出標的 → 觀測：連續兩週零增發 + 出現非計畫性淨賣出
證偽條件：連續兩週零增發且出現非計畫性淨賣出 → 執行既定減碼規則，不辯論
```

轉寫不出來，代表反面寫得不夠具體，回去補觀測指標。

## 禁止事項

- **不要用反面來對沖立場。** 反面的目的是讓判斷可被推翻，不是讓你兩邊都站。
  主論點該多明確就多明確，反面另外獨立成立。
- **不要把「執行風險」當反面。** 「管理層可能執行不力」對任何公司都成立，
  因此對這一家沒有資訊量。
- **不要省略你不喜歡的那一種。** 最該寫的往往是「力道不足」型——
  它沒有戲劇性，但真實世界的失敗多半長那樣。
