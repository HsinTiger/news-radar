# 框架：總編輯的最後一關

> 用途：文章與標題都寫完後的**最後一次通看**。
> 其他框架各管一段，這一份管**整體是否成立**——
> 標題、副標、子標題、開頭四者放在一起讀，像不像同一個人在說同一件事。
>
> 順序：`human-editorial-layer` → `sentence-clarity` → `de-ai-prose` → `title-engine` → **本框架**

## 為什麼需要單獨一關

前面每一關都只看局部。句子合格、標題合格、子標題合格，
但讀者**不是分開讀它們的**——他先看標題，接著副標，掃過子標題，才決定要不要讀。

那四樣東西是一個組合。組合失敗最常見的樣子是：每個零件都對，合起來沒有一條線。

## 一、副標：最常寫壞的地方

**副標的唯一職責是延伸標題的張力，不是介紹來源。**

實測失敗案例（2026-08-10）：

> 標題：多巴胺沒有捷徑
> 副標：Huberman Lab 花了九十分鐘教你大腦化學工具包。最誠實的部分，是他說「這個別用」的那幾秒。

標題很好，副標整句卻在講那集 podcast 做了什麼。**主詞是來源，不是讀者，也不是那個判斷。**
讀者不在乎誰講的，他在乎「所以我該改變什麼」。

三個檢查：

1. **主詞是誰？** 是來源名稱、主持人、機構名 → 重寫。
2. **拿掉來源名字，這句還成立嗎？** 不成立代表你在寫導讀，不是副標。
3. **它有沒有把標題往前推一步？** 只是換句話說標題 → 白費。

改法是把「來源做了什麼」換成「這件事對讀者意味著什麼」：

> ✓ 行為工具站得住腳，補充劑那一段證據就薄了。差別不在有沒有效，在有沒有人真的測過。

**名詞堆疊也在這裡處理。** 「大腦化學工具包」是三個名詞黏在一起，
唸出來會卡。副標要能被唸出來——**唸不順就是寫壞了**。

## 二、子標題連讀測試

把所有子標題抄成一行讀。它們應該像**一個人帶你想事情的順序**，
不是研究報告的章節目錄。

```
✓ 九十分鐘的工具包，和那幾秒的保留
  → 四種化學物質，用人話說
  → 行為工具相對站得住腳
  → 進入補充劑，證據明顯變薄
  → 「控制」這個詞的問題
```

這組是合格的：從「他說了什麼」走到「哪部分可信」再到「哪個詞有問題」，
有一條收斂的線。

不合格的樣子是每個子標題各自獨立、順序可以任意對調。
**能任意對調，就代表沒有論證推進。**

## 三、開頭與標題的握手

讀者點進來，是因為標題給了他一個期待。第一段必須**在三行內接住那個期待**，
否則他會覺得被騙。

- 標題丟出張力 → 第一段就要碰到那個張力，不要先鋪陳背景。
- 標題問了問題 → 第一段不必回答，但要讓他知道你聽見了那個問題。

## 四、整體通看的三個問題

1. **這篇文章，一句話說完是什麼？** 說不出來代表主軸還沒立。
2. **標題、副標、子標題、開頭，是同一個人的聲音嗎？**
   常見破綻：標題口語、副標學術、子標題報告體。
3. **有沒有哪一段是為了滿足規則而寫的？** 有就刪。
   規則是為了讓文章更好，不是為了被滿足。

## 邊界

這一關**只調整既有材料的呈現，不新增內容、不改變判斷**。
發現論證有洞，正確做法是回到 `counter-case-construction` 標明「查不到」，
不是在最後一關補一段推測把它填平。

也不必為了通過檢查而犧牲一個好句子。**這是最後一關，不是最嚴的一關**——
它要問的是「讀者會不會想讀下去」，不是「有沒有違規」。
