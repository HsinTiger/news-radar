# 框架：句子層的認知負擔

> 用途：分析型長文的逐句檢查，在 `human-editorial-layer` 改完結構之後跑。
> 核心原則：**提升可讀性不必犧牲密度或深度，要降低的是認知負擔。**
>
> 與其他文風框架的分工：
> `human-editorial-layer` 管思考路徑（段落之間），
> `de-ai-prose` 管手癖（標點與句型），
> 這一份管**單句是否好懂**。

## 八條

### ① 讓主幹容易辨認

主詞、主要動詞、受詞之間不要隔太多修飾語。

一句話同時裝背景、條件、原因、結果、例外和補充，就該拆。
**拆開之後通常會發現很多東西根本不用講。**

### ② 不要把動作藏在抽象名詞裡

最常見的語言癌。動詞被名詞化，再補一個空洞的動詞去帶它：

| ✗ | ✓ |
|---|---|
| 進行評估 | 評估 |
| 做出判斷 | 判斷 |
| 產生改變 | 改變 |
| 對市場造成影響 | 影響市場 |

看到「進行／做出／產生／造成／實現／給予／加以」接抽象名詞，多半可以直接還原成動詞。

### ③ 每句要有清楚的主張

不要讓人讀到句尾才知道整句在說什麼。避免在單句裡塞：
多層條件、連續因果、多重轉折、大量插入語、名詞後接多層修飾。

**資訊多就拆成數句，再用前後關係連起來。** 句號比逗號便宜。

### ④ 指涉對象要能立刻辨識

代名詞、指示詞、省略的主詞都要能一眼對上。

> ✗ 公司告訴供應商，他們必須調整價格。
> （「他們」是公司還是供應商？）
> ✓ 公司要求供應商調整價格。

中文常省略主詞，跨句時特別容易失焦。**「這」「該」「其」出現時，回頭確認指涉唯一。**

### ⑤ 先給理解所需的資訊，再給依賴它的判斷

不要先用一個還沒解釋的概念，再回頭補說明。

> ✗ 這造成典型的需求側規模經濟，也就是使用者愈多，產品對其他使用者的價值愈高。
> ✓ 使用者愈多，產品對其他使用者的價值也愈高。這種現象稱為需求側規模經濟。

同一組資訊，換個順序就從難懂變好懂。**術語放在解釋之後，不是之前。**

### ⑥ 刪

逐詞、逐句、逐段問：**刪掉之後，讀者得到的資訊、邏輯關係與語氣是否完全不變？**
完全不變就刪。

常見可刪：
- 重複前一句
- 宣布「接下來要討論 X」，下一句才真的開始討論
- 只負責營造氣勢
- 把簡單概念包裝成抽象說法
- 用很多字講一個已有更直接說法的概念

### ⑦ 抽象詞要落地

用到「價值」「影響」「策略」「轉型」「差異化」「創新」「能力」「競爭力」時，
確認讀者知道它**具體指什麼**。

> ✗ 這項策略提升了品牌價值。
> ✓ 這項策略提高了品牌在高階市場的辨識度，也讓平均售價提高。

### ⑧ 比較級要交代基準

看到這些詞就檢查「跟什麼比」：
**更高、更快、更有效、更便宜、更成功、大幅、明顯、主要、領先。**

> ✗ 公司的成長速度明顯加快。
> ✓ 公司營收年成長率從前一年的 8% 提高到 17%。

分析型文章尤其嚴格：沒有基準的比較級，等於沒有資訊。

## 可機器檢查的部分

②④⑧ 有明確的字面特徵，不必靠自覺。這很重要——本管線已經證明
**光靠指令攔不住模型的手癖**（`de-ai-prose` 明文禁止對仗句，Opus 與 Flash 都照犯）。

因此下列已寫進 composer 的 audit，會直接回報位置：
- **②** 「進行／做出／產生／造成」+ 抽象名詞
- **⑧** 比較級與程度副詞，附近沒有數字或對照對象

①③⑤⑥⑦ 需要語意判斷，仍由寫手自我檢查。

## 順序

在 `human-editorial-layer` 之後、`title-engine` 之前。
**結構沒改對就修句子，是替歪掉的房子刷油漆**；
但標題要從改乾淨的內文長出來，所以句子先於標題。
