# 框架：人話編輯層

> 用途：初稿完成後的最後一道編輯，在下標題之前跑。
> `de-ai-prose` 是減法（清手癖），這個是加法（重建思考路徑）。
> 兩者不能互相取代：一篇沒有破折號、但依然像研究摘要的文章，仍然不合格。

## 這一層在治什麼

症狀是：**意思都對，但句子不像一個人真的會這樣講。**
讀者看得懂每一句，卻感覺不到有人在跟他說話。

病因幾乎都是同一個——文章是「研究摘要 → 一段一段翻成中文」的產物。
材料按照被找到的順序排列，而不是按照**讀者需要被說服的順序**。

診斷方法最快：**把所有子標題抄下來連著讀。**

```
✗ 一個沒被輕鬆打發的挑戰 → 門格爾的那一句話 → 亞當·斯密問題真的存在嗎
  → 邊沁最出人意料的設計
  讀起來像逐項報告研究結果
```

每個標題單獨看都合格，連起來卻沒有一條思考的線。這就是僵硬感的來源。

## 四道檢查（依序，不可跳）

### ① 意思檢查

問：**讀者讀完，最該改變的那個念頭是什麼？**

一篇文章只能有一個。寫不出來，代表初稿還沒有主軸，這時改句子沒有意義。

素材裡的「誰說了什麼」不是主軸。
- ✗ 主軸＝Collins 對斯密的重新詮釋　（這是題材）
- ✓ 主軸＝同情弱者，和能改變弱者的處境，是兩回事　（這是判斷）

### ② 邏輯檢查

問：**每一段為什麼接在上一段後面？拿掉會不會影響論證？**

把文章重排成一條問答鏈，而不是一份發言紀錄：

```
✗ A 說 X → B 反駁 → A 回應 → C 補充 → D 也有類似設計
✓ 我們以為是 X
  → 但如果不是呢
  → 真正麻煩的是這件事
  → 而它到現在還沒被回答
```

所有材料服務那條線。接不上的段落就刪，不要因為研究過就捨不得。

### ③ 人話檢查

逐句問：**這句話，一個聰明但不熟這題的朋友面前，你真的會這樣說嗎？**

典型的落差長這樣：

> ✗ Collins 的回應沒有迴避。她承認斯密確實受斯多葛學派影響，但認為他同時
>   受到十八世紀感傷主義的深刻塑造。

> ✓ Collins 沒有否認這件事。斯密確實深受斯多葛學派影響。
>   但她認為，只看到這一面，就會漏掉另一半的斯密。

差別不在用詞難易，在**呼吸**。前者把三個子句壓進一句，後者讓判斷單獨站一行。

### ④ 節奏檢查

問：**每一段是不是都長得一樣？**

最常見的失敗是每段都是「主張 → 解釋 → 因此」。三段之後讀者就麻痺了。

可用的節奏工具：長句後接短句、判斷單獨成段、丟一個具體例子、問一個反問。
不必每段都用，但**一篇文章裡至少要有兩種不同的段落形狀**。

## 順序為什麼不能跳

①②是結構，③④是表面。**結構沒對就潤句子，是在替一棟歪掉的房子刷油漆。**
實務上①②改完，一半的僵硬感會自己消失，因為那些句子本來就是為了填補
缺失的邏輯而寫的。

## 邊界

這一層**不新增素材、不改變判斷**。發現論證缺一塊證據時，
正確做法是明寫「這裡查不到」（見 `counter-case-construction`），
不是自己補一段推測把洞填起來。

改完之後才下標題，用 `title-engine`——標題要從**改完的主軸**長出來，
不是從初稿的題材。
